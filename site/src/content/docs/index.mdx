## Choose where to start

| Your situation | Start here | What you will finish with |
| --- | --- | --- |
| Your team already runs Quirebase | [First reference](/getting-started/quickstart/) | One saved Item, a readable PDF, and a private note |
| You have a DOI, bibliography, or PDFs | [Import references](/guides/import/) | A reviewed Import Batch committed to your Workspace |
| You know a topic or title | [Search external sources](/guides/discovery/) | Candidates you can review before importing |
| You need to find saved research | [Search and organize Library](/guides/library-management/) | A filtered Library, Tags, or a saved view |
| You want to read with colleagues | [Project collaboration](/guides/collaboration/) | A Project working set with shared Annotations |
| You run the installation | [Deploy Quirebase](/administration/deployment/) | Web and worker processes with persistent data |
| You are connecting a program | [HTTP API](/developers/http-api/) or [MCP](/developers/mcp/) | An authenticated client using an explicit Workspace |

## Follow the research workflow

1. [Choose a Workspace and add a reference](/getting-started/quickstart/).
2. [Add a PDF revision or supplementary file](/guides/files/).
3. [Read, annotate, and check saving](/guides/pdf-annotations/).
4. [Add the Item to a Project](/guides/collaboration/) when you need a shared reading context.
5. [Export citations or a document bundle](/guides/citations-and-exports/).

An **Item** is the reference record; a **File Revision** is one primary PDF attached to it. A
**Workspace** governs access to the Library, while a **Project** organizes a working set inside
that Workspace. The [concept guide](/concepts/research-library/) explains these terms with an example.

## When something does not work

Use the [troubleshooting guide](/knowledge-base/troubleshooting/) for a pending import, failed PDF,
missing action, or unsaved Annotation. The [FAQ](/knowledge-base/faq/) answers visibility and data-lifetime questions.

Quirebase is alpha software. These pages describe the current development version. Before an
upgrade, read the target release's instructions. The generated [API Reference](/reference/api/)
uses the FastAPI schema's English descriptions; the integration tutorials are available in English
and Chinese. An installation's own `/docs` and `/openapi.json` describe its running release.
