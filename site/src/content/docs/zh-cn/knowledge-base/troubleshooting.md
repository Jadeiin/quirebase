---
title: 按现象排查问题
description: 先确认当前状态，再处理导入、Worker、权限、批注保存、下载及配置问题。
---

从具体症状开始，查看当前资源或任务状态，再按下面的步骤处理。排查时使用实例实际的版本、工作区和配置。

| 你看到的现象 | 先检查什么 |
| --- | --- |
| 有导入预览，但文献库没有条目 | 是否完成确认，目标工作区是否正确 |
| 无法确认导入是否完成 | 使用“检查导入状态”查看结果 |
| PDF 处理一直等待 | Worker 是否运行，数据库及存储是否与 Web 一致 |
| 找不到操作按钮 | 成员关系、角色、冻结或归档状态及资源关联 |
| 同事看不到标记 | PDF 修订版、创建时保存目标和显示来源 |
| 反向代理后登录成功，但修改失败 | 公网 Origin、主机白名单和 HTTPS Cookie |
| 改环境配置后没有效果 | 是否存在管理员保存的运行时覆盖值 |

## 导入或 PDF 处理一直等待

1. 从“导入历史”或条目“文件”分区重新查看保留的状态。
2. 运维检查独立 Worker 是否运行。Compose 可使用 `make docker-ps`，并在 `make docker-logs` 中查看 Worker 的记录（按 Ctrl+C 结束日志跟踪）。
3. 核对 Web 和 Worker 使用同一数据库、对象后端，以及适用的 bucket 和 prefix。
4. 用该实例配置运行 Doctor，查看失败项。

替换 Worker 时应保留稳定 executor ID。旧 executor 永久退役时，按[持久化恢复](/zh-cn/administration/maintenance/)处理。

## 导入结果不确定，或找不到导入条目

页面无法确认是否完成时，点击“检查导入状态”。若已提交，使用“查看已导入文献”。
文献库为空时，再核对工作区和当前筛选，包括导入批次筛选。

元数据缺失时逐项查看诊断。使用支持的标识符，给 ISBN-10 加 `ISBN:` 前缀；
临时来源失败可以按页面提供的操作重试，也可以明确选择基础 PDF 后再补元数据。
可用输入格式见[导入指南](/zh-cn/guides/import/)。

## 按钮缺失或访问被拒绝

请工作区所有者或管理员检查你的成员状态和角色。接着核对工作区是否冻结、项目是否归档，以及你是否已加入目标项目。
需要恢复工作区或调整角色时，按[成员管理](/zh-cn/administration/workspaces-and-members/)操作。

## 批注报告保存失败

先保持阅读器打开并检查保存状态，再核对网络、新批注保存目标、项目是否活跃、项目条目关联是否仍然存在。
并发修改可能要求先检查当前资源，再重试。

保存恢复后，重新打开同一 PDF 修订版，并勾选对应来源核对批注。

## 下载或导出失败

批注导出过期时，应在仍有权限的情况下重新生成。
开启 S3 直接签名下载时，检查浏览器能否访问 endpoint，存储桶 CORS 是否允许应用 Origin、Range 请求和必要响应头。
`garage` 这类地址可能只在容器网络内可用，此时应使用应用流式下载。

## 代理后可以登录，但无法修改

将 `QUIREBASE_EXTERNAL_ORIGIN` 设为准确的公网协议、主机和端口，在 `QUIREBASE_ALLOWED_HOSTS` 中加入公网主机，
并在 HTTPS 下启用安全 Cookie。重启或重建相关服务后，从配置的应用 Origin 再试。

## 修改配置后没有效果

先核对进程工作目录和环境，再检查管理员页面的“设置”。
支持的运行时值会覆盖环境默认值。数据库、对象存储、Origin 和 Worker 等部署设置，需要让各进程使用一致配置并重启。
详见[配置优先级](/zh-cn/administration/configuration/)。

## 提供便于定位的反馈

记录 Quirebase 版本、失败任务及工作区上下文、脱敏后的错误 `code` 和 `message`，以及可取得的 `X-Request-ID`。
运维可以据请求 ID 关联日志。提交公开反馈前，对日志、截图和连接地址中的凭据及私人资料脱敏。
仓库[问题跟踪](https://github.com/Jadeiin/quirebase/issues)是公开反馈入口。
