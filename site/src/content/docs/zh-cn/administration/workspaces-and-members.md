---
title: 管理工作区与成员
description: 按任务分配角色，邀请已有用户，转移所有权，并处理归档、冻结和删除。
---

工作区所有者和管理员可在“工作区设置”中邀请成员、分配角色和管理工作区状态。

## 按对方要做的工作选择角色

根据同事要完成的任务选择角色：

| 角色 | 常用操作 |
| --- | --- |
| `owner` 所有者 | 管理工作区与管理员、转移所有权、永久删除已归档工作区 |
| `admin` 管理员 | 管理普通成员、审核内容、删除条目 |
| `editor` 编辑者 | 导入文献、维护元数据和文件、分配标签、组织项目 |
| `reviewer` 评审者 | 共享批注、回复和讨论 |
| `viewer` 查看者 | 阅读、导出内容，记录私人笔记 |

五种角色在活跃工作区中都可以创建自己的私人批注。
精确授权由[自动生成权限矩阵](https://github.com/Jadeiin/quirebase/blob/main/docs/architecture/authorization-matrix.md)维护。

## 邀请已经有账号的用户

1. 确认对方已经拥有本实例账号；没有账号时，先由实例管理员通过账号邀请完成创建。
2. 打开“工作区设置 → 邀请”。
3. 输入精确用户名，选择页面提供的角色和有效期，再点击“创建邀请”。
4. 复制一次性链接交给目标用户。
5. 对方以该用户身份登录后接受，可以使用链接，也可以从“我的工作区”查看收到的邀请。
6. 在“工作区设置 → 成员”中确认已经出现活跃成员关系。

链接过期或被撤销后，重新创建邀请。暂停的成员可通过“重新激活”恢复；终止后重新加入则需要新邀请。

## 修改角色或成员状态

在“成员”中找到目标用户，选择新的角色或状态操作。所有者管理管理员，管理员管理普通成员。

- “暂停”会移除有效访问权，但保留内容、作者记录和项目选择。
- “重新激活”在其他条件允许时恢复这份暂停成员关系的有效参与。
- “终止”结束当前成员关系并移除项目选择，保留内容和作者记录。重新加入后可重新安排项目参与。

活跃的非所有者成员可以离开一个活跃且未冻结的工作区。离开后，已经贡献的文献和讨论保留在工作区中。

## 转移或重新指派所有权

当前所有者为合适的活跃成员执行“转移所有权”，并阅读确认信息。接收者成为所有者，原所有者成为管理员。
所有者离开或移除其成员关系前，应先完成转移。

所有者账号停用、需要交接时，实例管理员可填写理由，把所有权重新指派给活跃用户。

## 归档、冻结、恢复和删除

| 操作 | 在哪里执行 | 作用 |
| --- | --- | --- |
| 归档或恢复 | 有权限时，使用“工作区设置 → 高级” | 保留可读、可导出的工作区，或在之后恢复 |
| 重建索引 | 有权限时，使用“高级”中的维护操作 | 重建这个工作区的文献库搜索投影 |
| 冻结或解冻 | 实例治理 | 将工作区设为只读，或恢复冻结前的状态 |
| 永久删除 | “高级”，仅所有者可执行 | 移除已归档且未冻结的工作区及其中内容 |

恢复或管理已冻结的工作区时，先请实例管理员解冻。永久删除前，先完成[备份](/zh-cn/administration/maintenance/)。
删除项目或移除一个项目条目关联的范围不同，见[项目协作](/zh-cn/guides/collaboration/)。
