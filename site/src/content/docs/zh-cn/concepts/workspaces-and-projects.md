**Workspace（工作空间）** 是条目、文件、标签、讨论和项目的数据治理及权限边界。
所有研究资源都有唯一的工作空间归属。系统没有独立的“个人工作空间”和“共享工作空间”类型；
新用户自动获得的工作空间遵循同一套规则。

**Project（项目）** 在一个工作空间内组织条目集合，并保存项目批注和讨论。
项目没有所有者；创建者记录的是来源信息，不代表额外的权限角色。

## 两个层次的权限

实例的 System Role（系统角色）为 `administrator` 或 `member`，管理用户和实例操作。
实例管理员不会因此自动获得工作空间研究数据的访问权。

Workspace Role（工作空间角色）为 `owner`、`admin`、`editor`、`reviewer` 或 `viewer`。
服务器结合角色、资源关系和生命周期判断具体操作，例如 `item.update` 或 `item.delete`。
有效的数据访问同时要求用户和工作空间成员关系处于活跃状态。作者身份与操作权限分别记录。

项目参与不附带额外的工作空间权限，也不授予资料库中原始条目的访问权。
托管参与模式限制项目协作上下文的可发现性，不会让其中的原始条目在工作空间内变成私有资料。

## 项目参与模式

| 模式 | 可发现性与参与方式 |
| --- | --- |
| `workspace` | 所有活跃成员均可发现并隐式参与 |
| `open` | 所有活跃成员均可发现，可自行加入或退出 |
| `managed` | 参与者和工作空间管理者可发现，由治理操作选择参与者 |

## 只读与成员状态

- 冻结工作空间会阻止修改，但保留活跃成员的读取、下载和导出权限，也不会赋予实例管理员内容访问权。
- 归档保留工作空间或项目，以供恢复，并影响可用操作。
- 暂停成员关系会移除有效访问权，但保留项目选择。
- 终止成员关系会移除访问权及项目选择。重新加入需要新邀请，并创建新一代成员关系。

移除项目中的条目关联，会永久删除该关联的项目批注及回复；条目、文件、私人批注和其他项目关联仍会保留。
这与删除工作空间中的原始条目是不同的操作。

用户停用后，工作空间所有者的指派仍保留。实例管理员可填写原因，将所有权显式重新指派给活跃用户。
完整协作步骤见[协作指南](/zh-cn/guides/collaboration/)。
