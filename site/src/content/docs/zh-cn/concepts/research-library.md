假设你在一个工作区保存一篇期刊文章，先上传出版版 PDF，后来又补了一份修正版 PDF。
此时仍然只有**一个条目（Item）**，但有**两份文件修订版（File Revision）**。
对第一份 PDF 第三页所做的私人笔记，保存在第一份修订版上。

如果把这个条目加入两个项目，它们引用的是同一条工作区文献记录，各自保存项目批注和讨论。
修改条目元数据会更新共同使用的记录；私人笔记和各项目的阅读上下文则保持各自的可见范围。

## 先辨认你正在编辑什么

| 术语 | 它代表什么 | 例子 |
| --- | --- | --- |
| 条目（Item） | 工作区中的一条文献记录 | 文献库里的这篇期刊文章 |
| Work | 条目的结构化书目信息，采用 Commonmeta 格式 | 标题、类型、标识符、贡献者、日期 |
| 文件修订版（File Revision） | 一份不可变的主 PDF | 出版版 PDF 或修正版 PDF |
| 附件（Attachment） | 条目的补充文件 | 支持数据或代表图片 |
| 批注（Annotation） | 定位到某份修订版某页的标记 | 出版版 PDF 第三页的高亮 |
| 批注回复（Annotation Reply） | 继承批注可见范围的回应 | 同事对项目高亮的回复 |
| 标签（Tag） | 显式分配给条目的工作区分类 | “方法”或“待读” |
| 项目（Project） | 工作区中的协作文献集合 | 使用其中一部分文献的读书组 |
| 候选记录（Candidate Record） | 尚未写入文献库的元数据 | 导入预览中展示的记录 |
| 导入批次（Import Batch） | 源输入、候选、诊断及保留的确认结果 | 从一份书目文件准备出的批次 |

贡献者是文献中署名的个人或组织，按文献记录保存姓名、署名顺序等信息。

## 搜索、准备和确认分别产生什么结果

| 操作 | 查询或写入哪里 | 得到什么 |
| --- | --- | --- |
| 文献库搜索 | 已保存的工作区元数据和 PDF 提取文本 | 匹配的已保存条目 |
| 发现 | 外部学术来源 | 可供导入的搜索结果 |
| 标识符查找或导入准备 | 来源元数据或上传材料 | 供检查的候选记录与诊断 |
| 确认导入 | 当前选择的工作区 | 按批次及基础 PDF 选择创建条目 |
| 手工创建 | 当前选择的工作区 | 点击“创建条目”时创建 |

导入历史记录批次中的条目 ID，方便查找本次导入的文献。回执按实例设置的保留期保存，条目和文件长期保存在文献库中。

## 身份和生命周期

条目有自己的 UUID 和工作区归属。DOI 标识的是文献所描述的研究成果，多条记录可能使用同一 DOI，所以重复建议需要人工检查。
引用键是用于引文输出的可编辑名称。

条目先保存书目信息，随后可以添加 PDF 和附件。每份 PDF 修订版保存自己的页面与批注。
删除修订版会移除绑定的批注和缩略图；删除项目关联会移除该关联的项目批注与回复；删除条目会移除其文件及相关内容。
